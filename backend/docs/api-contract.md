# Kontrak API MVP

API menggunakan JSON dan sesi cookie HttpOnly. Semua route `/api` selain health-check dan route auth memerlukan login; data selalu dibatasi pada tenant sesi.

## Status worker

`offered` → `preactive` → `active` atau `inactive`; dari `active` hanya dapat berpindah ke `inactive`, sedangkan `inactive` dapat diaktifkan kembali. Perubahan status diminta oleh Admin. Aktivasi hanya diizinkan dari `preactive`/`inactive` jika semua jenis dokumen wajib memiliki catatan terbaru berstatus `valid` yang tanggal berlakunya mencakup hari ini (UTC). Penonaktifan dapat langsung berlaku atau dijadwalkan; backend memproses jadwal yang jatuh tempo saat startup dan setiap menit, mencatat riwayat status, menghapus jadwal, dan mencabut tautan presensi.

Jenis dokumen disimpan per tenant dalam katalog dinamis yang kosong saat tenant baru dibuat. Tidak ada jenis bawaan dan tidak ada pilihan default pada formulir pekerja; admin menambahkan kebutuhan perusahaan sendiri. Kode baru dihasilkan dari nama yang dinormalisasi (contoh `Sertifikat K3` menjadi `sertifikat_k3`), dan tetap stabil ketika nama diedit. Dokumen dicatat sebagai riwayat append-only, dan catatan terbaru untuk tiap jenis menjadi acuan kelayakan. Jenis dengan kode legacy `mcu`, `pkwt`, dan `sim` tetap memerlukan tanggal kedaluwarsa untuk kelayakan aktif; jenis lain tidak mensyaratkan kedaluwarsa secara default.

## Endpoint

- `GET /api/health` — health check server.
- Socket.IO pada origin API (`/socket.io`) menyediakan event real-time untuk sesi login yang valid. Autentikasi memakai cookie HttpOnly `hrd_session`; koneksi bergabung otomatis ke room tenant berdasarkan sesi (client tidak dapat memilih tenant). Server memvalidasi status/versi sesi saat handshake dan memeriksanya kembali tiap menit. Event tenant-scoped: `worker_changed`, `attendance_updated`, `approval_updated`, `documents_updated`, `dashboard_updated`, `settings_updated`, `user_changed`, dan `history_updated`; payload hanya membawa aksi dan metadata minimum, bukan data pribadi pekerja. Mutasi sukses dipancarkan setelah respons selesai; Check-In/Check-Out/pengajuan publik dipancarkan sesudah transaksi commit. Koneksi dapat memakai WebSocket atau fallback polling Engine.IO.
- `POST /api/auth/register` — membuat tenant dan akun admin pertama. Request: `{ "company_name", "full_name"?, "email", "password" }`; nama lengkap opsional untuk kompatibilitas klien lama, kata sandi minimal 12 karakter dan maksimal 72 byte UTF-8. Respons identitas mencakup `id`, `full_name`, `email`, `role`, `profile_photo_url`, dan `company_name`.
- `POST /api/auth/login` — Request: `{ "email", "password" }`.
- `POST /api/auth/logout` — menghapus cookie sesi.
- `GET /api/auth/me` — identitas pengguna dan tenant aktif, termasuk nama lengkap, role, dan URL foto profil.
- `PATCH /api/profile` — mengubah nama akun sendiri. Request: `{ "full_name" }`.
- `POST /api/profile/photo` — mengunggah foto profil akun sendiri sebagai multipart field `photo`; hanya JPG/PNG valid, maksimal 900 KiB setelah kompresi browser. Data biner disimpan di MySQL dan respons memberikan `profile_photo_url` untuk tampilan segera.
- `GET /api/profile/photo` — menyajikan foto profil JPG/PNG milik sesi aktif dengan header no-store.
- `PATCH /api/profile/password` — memverifikasi password lama lalu menggantinya. Request: `{ "current_password", "new_password", "confirm_password" }`; password baru harus cocok, berbeda dari password lama, 12–72 byte UTF-8. Password di-hash bcrypt; sesi lama dicabut dan sesi saat ini mendapat cookie baru.
- `GET /api/admin/users` — daftar akun pada tenant sesi; khusus Admin.
- `POST /api/admin/users` — membuat akun dalam tenant sesi; khusus Admin. Request: `{ "full_name", "email", "password", "role" }`; role: `admin`, `hr_manager` (ditampilkan sebagai HR Staff), atau `viewer`. Email unik global; konflik mengembalikan `409`.
- `PATCH /api/admin/users/:id` — mengubah `role` dan/atau `is_active` untuk akun dalam tenant sesi; khusus Admin. Request: `{ "role": "hr_manager", "is_active": true }` (masing-masing field opsional, setidaknya satu wajib). Sesi akun target dicabut; admin tidak dapat menurunkan/menonaktifkan dirinya sendiri atau menonaktifkan/menurunkan admin aktif terakhir.
- `POST /api/admin/users/:id/reset-password` — reset password akun dalam tenant sesi; khusus Admin dan tidak dapat dipakai untuk akun sendiri. Request: `{ "new_password" }`; password harus 12–72 byte UTF-8, disimpan dengan bcrypt, dan seluruh sesi target dicabut.
- `GET /api/dashboard` — ringkasan status pekerja, jumlah dokumen kedaluwarsa atau yang memasuki ambang peringatan efektif, jumlah klaim presensi tenant berstatus `pending`, tanggal awal/cutoff default, dan jumlah hari ambang default. Ambang spesifik jenis dokumen mengalahkan default tenant.
- `GET /api/subscription` — paket dan penggunaan kuota tenant aktif: `{ "plan", "active_workers", "worker_limit" }`. Tenant baru dan tenant lama yang dimigrasikan menggunakan paket `free` dengan batas 20 pekerja aktif. Saat batas tercapai, penambahan pekerja, impor masal, dan aktivasi pekerja ditolak dengan HTTP `409` serta kode `WORKER_QUOTA_EXCEEDED`. Pembelian paket Pro/Enterprise belum tersedia.
- `GET /api/history?limit=100` — hingga 200 audit event terbaru untuk tenant aktif, berisi waktu, snapshot nama/role pelaku, aksi, jenis/ID entitas, dan deskripsi ringkas. Hanya Admin dan HR Staff; Viewer menerima `403`. Log mencakup perubahan penting pekerja, dokumen, presensi, approval, user, serta pengaturan, dan tidak menyimpan password atau bukti berkas.
- `GET /api/admin/document-settings` — membaca preferensi ambang peringatan kedaluwarsa tenant; khusus Admin. Nilai default 30 hari bila belum disimpan, sebagai fallback jenis dokumen.
- `PATCH /api/admin/document-settings` — menyimpan `{ "warning_threshold_days": 30 }`; nilai bilangan bulat 1–365 hari; khusus Admin.
- `GET /api/admin/attendance-settings` — status konfigurasi salt tenant (tidak mengembalikan salt); khusus Admin.
- `PATCH /api/admin/attendance-settings` — menyimpan `{ "anti_mock_location_enabled": true }`; khusus Admin. Nilai konfigurasi tenant dikembalikan tanpa salt.
- `POST /api/admin/attendance-settings/salt` — membuat atau merotasi salt acak 256-bit tenant. Request `{ "confirm_rotation": true }`; khusus Admin. Merotasi salt mencabut seluruh tautan presensi lama.
- `GET /api/admin/attendance-locations` — daftar titik geofence tenant beserta radius dan aktivitas yang wajib dilakukan di area tersebut; khusus Admin.
- `POST /api/admin/attendance-locations` — tambah titik. Request `{ "name", "latitude", "longitude", "radius_meters", "allowed_activities": ["check_in", "check_out", "off", "permission", "leave", "sick"] }`; radius 25–5000 meter. `allowed_activities` adalah nama field API lama: aktivitas yang dicentang wajib berada dalam radius salah satu lokasi yang mencentangnya, sedangkan aktivitas yang tidak dicentang di lokasi mana pun boleh dilakukan dari luar area. Array kosong valid; khusus Admin.
- `DELETE /api/admin/attendance-locations/:id` — hapus titik tenant; khusus Admin.
- `GET /api/attendance?date=YYYY-MM-DD` — rekap harian pekerja aktif tenant sesi termasuk koordinat, status persetujuan, serta ketersediaan bukti; tanggal opsional default tanggal database. Admin, HR Staff, dan Viewer.
- `GET /api/attendance/month?month=YYYY-MM` — pekerja aktif beserta catatan presensi bulan terpilih; data tenant-scoped. Admin, HR Staff, dan Viewer.
- `PATCH /api/attendance/:workerId/status` — mencatat atau mengubah status manual presensi; khusus Admin.
- `PATCH /api/attendance/:workerId/approval` — menyetujui/menolak pengajuan; khusus Admin. Penolakan dapat diajukan ulang pekerja.
- `GET /api/attendance/:workerId/evidence?date=YYYY-MM-DD` — menyajikan bukti Dinas tenant-scoped untuk pembacaan role terautentikasi.
- `DELETE /api/attendance/:workerId?date=YYYY-MM-DD` — mengarsipkan log presensi secara soft-delete; hanya Admin. Log tidak dihapus permanen dan tidak lagi muncul di rekap.
- `POST /api/workers/:id/attendance-link` — membuat atau mengambil kembali tautan statis pekerja aktif pada tenant sesi; memerlukan role Admin/HR Staff. Token adalah HMAC deterministik dari tenant, worker, salt tenant, dan kunci aplikasi; database hanya menyimpan hash untuk revokasi. Tautan tetap sama hingga salt dirotasi. Jika salt belum dibuat, merespons `409 ATTENDANCE_SALT_NOT_CONFIGURED`; Admin harus membuat salt pada Pengaturan Presensi terlebih dahulu.
- `DELETE /api/workers/:id/attendance-link` — mencabut tautan presensi aktif; khusus Admin.
- `GET /api/public/attendance?worker_id=...&token=...` — memvalidasi tautan dan menampilkan profil pekerja, aturan lokasi aktif, status Anti-Mock Location, status/koordinat presensi hari ini, dan maksimum 30 catatan.
- `POST /api/public/attendance` — check-in/out meminta `worker_id`, `token`, `action`, `latitude`, dan `longitude`; `location_id` tidak diperlukan. Jika Anti-Mock Location aktif, request juga harus memuat `is_mocked`, `location_accuracy` (maksimal 1.000 m), dan `location_speed`; sinyal mock, akurasi tidak memadai, kecepatan tidak masuk akal, atau perpindahan historis di atas 300 m/s ditolak. Pemeriksaan ini best-effort: browser tidak dapat membuktikan keaslian GPS dan sinyal klien dapat dimanipulasi. Backend tetap menegakkan aturan lokasi tenant: jika aktivitas dicentang pada satu atau lebih lokasi, koordinat harus berada dalam radius salah satu lokasi tersebut dan lokasi yang cocok dicatat; jika tidak dicentang pada lokasi mana pun, aktivitas boleh dilakukan di luar semua area geofence. Dinas memakai `request_type: "dinas"`; Check-In mengirim multipart `evidence` JPG/PNG valid maksimal 900 KiB, tanpa batas geofence, lalu menunggu persetujuan HR. Check-Out melengkapi catatan Dinas tanpa foto kedua. Off/Izin/Cuti/Sakit memakai `action: "request_status"` dan `request_type`; pengajuan tersebut mengikuti aturan geofence yang sama sebelum menunggu persetujuan HR.
- `GET /api/workers?status=active` — daftar pekerja tenant, persyaratan, dokumen, dan rekomendasi kelayakan. Filter status opsional: `offered`, `preactive`, `active`, `inactive`.
- `POST /api/admin/workers/import` — impor 1–500 baris pekerja JSON; khusus Admin. File `.xlsx` diproses di browser dan tidak dikirim ke server. Baris dengan nama/NIK/email duplikat dilewati; validasi per baris dikembalikan pada `created`, `skipped`, dan `errors`. Backend menolak impor jika kuota pekerja aktif paket Free telah penuh.
- `PATCH /api/workers/:id` — mengubah data pekerja dan pilihan dokumen wajib; khusus Admin. Email duplikat ditolak dengan `409`; jenis dokumen nonaktif yang sudah menjadi persyaratan pekerja tetap dapat dipertahankan.
- `GET /api/departments` — daftar pilihan departemen/divisi yang tersimpan untuk tenant aktif.
- `GET /api/document-types` — katalog jenis dokumen tenant aktif (termasuk yang nonaktif agar nama riwayat tetap dapat ditampilkan), berikut `warning_threshold_days` (1–365 atau `null` untuk mengikuti default tenant).
- `POST /api/admin/document-types` — menambah jenis dokumen untuk tenant sesi; khusus Admin. Request: `{ "name" }`; nama 1–100 karakter, disimpan lowercase dengan spasi dirapikan, nama duplikat ditolak (`409`), dan kode dibuat dari nama (slug huruf kecil dengan underscore, misalnya `sertifikat_k3`; suffix angka dipakai jika kode sudah terpakai).
- `PATCH /api/admin/document-types/:code` — mengubah `name`, `is_active`, dan/atau `warning_threshold_days`; khusus Admin. Ambang menerima bilangan bulat 1–365 atau `null` untuk kembali ke default tenant. Jenis nonaktif tidak tersedia untuk pekerja baru; untuk pekerja yang sudah memiliki persyaratan tersebut, dokumen masih dapat dicatat hingga kewajiban terpenuhi. Catatan lama tidak dihapus. Kode tidak berubah ketika nama diedit.
- `POST /api/workers` — membuat worker berstatus `offered`; Admin dan HR Staff. Viewer hanya baca. Request mencakup `{ "full_name", "email", "phone_number", "department", "position", "contract_type", "offer_date?", "required_document_types": ["sertifikat_k3"] }`.
- `GET /api/workers/:id` — detail pekerja, dokumen, kelayakan, dan riwayat status.
- `DELETE /api/workers/:id` — mengarsipkan pekerja; hanya Admin. Data pekerja dan catatan terkait tetap tersimpan, dan tautan presensi dicabut.
- `GET /api/workers/:id/eligibility` — rekomendasi kelayakan tanpa mengubah status.
- `POST /api/workers/:id/documents` — mencatat dokumen; Admin dan HR Staff. Request: `{ "type", "status", "target_completion_date?" }` untuk `pending`; `{ "type", "status", "valid_from?", "valid_until?" }` untuk `valid`/`expired`; `rejected` tidak menyimpan tanggal.
- `DELETE /api/workers/:id/documents/:documentId` — mengarsipkan catatan dokumen secara soft-delete; hanya Admin.
- `PATCH /api/workers/:id/status` — perubahan status; khusus Admin. Request `{ "status" }` atau `{ "status": "inactive", "effective_date": "YYYY-MM-DD" }`. Tanggal mendatang menjadwalkan nonaktif; tanggal hari ini, lampau, atau yang tidak diberikan menonaktifkan langsung. Status `active` memerlukan semua dokumen wajib valid saat ini.

Sukses dikembalikan sebagai `{ "data": ... }`; error menggunakan `{ "error": "..." }`. `401` berarti sesi diperlukan/tidak valid, `403` izin tidak cukup, `404` resource tidak ditemukan dalam tenant, `409` konflik kelayakan/data, dan `400` input tidak valid.

Email pengguna unik secara global pada versi MVP agar proses login dapat menentukan satu tenant. Indeks menggunakan SHA-256 atas email yang dinormalisasi, bukan kolom `VARCHAR(254)` langsung, untuk kompatibilitas batas panjang indeks MySQL.

Tautan presensi adalah kredensial bearer statis: HMAC-SHA256 atas versi protokol, tenant, ID pekerja, salt tenant acak 256-bit, dan `JWT_SECRET`. URL memakai `worker_id` dan token; salt dan kunci aplikasi tidak pernah dikirim ke browser. Database menyimpan salt nullable di `tenant_attendance_settings` serta hash token untuk status revokasi; preferensi Anti-Mock Location dapat tersimpan sebelum salt dibuat. Salt hanya dapat dibuat/dirotasi Admin; rotasi membatalkan semua link lama, yang kemudian perlu dibuat dan dibagikan ulang. `JWT_SECRET` wajib dipertahankan karena perubahan nilainya juga membatalkan link. Tabel `tenant_attendance_locations` memuat titik, radius, dan aktivitas yang diwajibkan di masing-masing area per tenant; untuk aktivitas yang diwajibkan pada beberapa area, pekerja cukup berada di dalam radius salah satunya, dan aktivitas tanpa area wajib boleh dilakukan dari mana saja. API memvalidasi jarak server-side. Anti-Mock Location memeriksa sinyal dari klien, kualitas akurasi, kecepatan, serta lompatan lokasi yang mustahil dari riwayat server; ini tidak dapat membuktikan GPS asli dari browser dan tidak tahan terhadap klien yang dimodifikasi. Untuk attestation yang dapat diandalkan, diperlukan aplikasi native dan mekanisme integritas perangkat. Tabel `attendance` mencatat lokasi yang cocok, status permintaan/persetujuan, serta bukti Dinas. Tile OpenStreetMap publik dipakai untuk MVP dengan atribusi dan sesuai kebijakan penggunaannya. Foto bukti disimpan sebagai BLOB maksimum 900 KiB sesuai `max_allowed_packet` MariaDB aktif 1 MiB. Tetapkan retensi lokasi/bukti sebelum produksi. Tanggal kerja dan waktu memakai timezone koneksi/database; atur timezone database ke timezone operasional perusahaan. Link ditolak jika pekerja tidak aktif atau token dicabut. Jangan bagikan token di kanal publik.

Role `admin` dan `hr_manager` dapat mengelola pekerja serta meninjau presensi/pengajuan; hanya `admin` yang dapat mengelola status/role user, katalog dokumen, salt, dan lokasi geofence. Semua query dibatasi ke tenant sesi. Admin tidak dapat menghapus akses admin terakhir. Semua endpoint profil/password memerlukan sesi dan hanya mengubah akun pemilik sesi. Foto profil dan bukti Dinas JPG/PNG divalidasi dari signature berkas, dibatasi maksimal 900 KiB, dan disimpan sebagai BLOB MySQL. Password akun baru dan perubahan/reset password disimpan sebagai bcrypt hash. Perubahan password, role, dan status meningkatkan versi sesi untuk mencabut token. Status user nonaktif memblokir login dan sesi berikutnya.

Nama pekerja, alamat, departemen/divisi, posisi, area kerja, nama akun/perusahaan, dan nama jenis dokumen disimpan lowercase setelah trim dan peringkasan spasi. Frontend menampilkan nilai-nilai teks tersebut dengan uppercase tanpa mengubah nilai yang dikirim/disimpan. Email juga disimpan lowercase; departemen disimpan per tenant dan duplikasi variasi kapitalisasi/spasi dicegah dengan unique hash key. Daftar departemen dapat dipilih dari opsi tersimpan atau diketik sebagai nilai baru.

## Privasi

Informasi dokumen MCU dibatasi pada jenis, status, tanggal target selesai saat masih menunggu, dan tanggal masa berlaku saat valid/kedaluwarsa. MCU, PKWT, dan SIM wajib memiliki `valid_until` agar dapat memenuhi syarat aktivasi; sertifikasi boleh tidak memiliki tanggal kedaluwarsa. Status ditolak tidak menyimpan tanggal apa pun. Hasil pemeriksaan medis, catatan bebas, dan alasan status tidak menjadi bagian model data API.

Audit trail tenant tersimpan pada tabel `audit_events` dan menampilkan 100 aktivitas terbaru secara default (maksimal 200 per request). Setiap catatan menyimpan snapshot nama/role agar atribusi tetap terbaca setelah perubahan akun. Retensi/pembersihan log belum dikonfigurasi; tentukan kebijakan retensi sebelum produksi.
